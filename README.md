# kimi-verse: AI-ассистент оператора Ситуационного центра

**Прототип системы интеллектуального скоринга и маршрутизации входящих сообщений для государственных органов.**

## Суть решения

| Параметр | Описание |
| :--- | :--- |
|  **Пользователь** | Оператор Ситуационного центра / Аналитик акимата. |
|  **Проблема** | Сотни неструктурированных сообщений из чатов и соцсетей. Ручная сортировка ведет к задержкам реагирования, выгоранию сотрудников и потере критических сигналов в информационном шуме. |
|  **Ценность** | Автоматическое присвоение приоритета, извлечение сущностей (локация, тип проблемы) и генерация обоснования. Сокращение времени первичной обработки обращения с ~3–5 минут до 15–20 секунд. |

> **Принцип Human-in-the-loop:** Система не принимает финальные решения. Она готовит структурированные карточки для оператора, который утверждает или отклоняет рекомендацию.
>
> **ИИ-рекомендации:** Система автоматически формирует краткие рекомендации для оператора на основе объективного анализа текста обращения и метрик, извлечённых из входного сообщения.

## AI/ML подход и Explainability

Решение использует NLP и большие языковые модели (LLM) для многоуровневого скоринга, а не простую классификацию по ключевым словам:

1. **Оценка базовой угрозы** (Safety/Threat detection).
2. **Оценка масштаба** (количество затрагиваемых людей/объектов).
3. **Бонус за повторяемость** (кластеризация похожих жалоб по локации/теме).

**Объяснимость (Explainability):** Система не является «черным ящиком». Для каждого сообщения генерируется строгий JSON, который выводит в интерфейс:
* ✅ Топ-3 фактора, напрямую повлиявших на оценку.
* ✅ Индекс достоверности модели (`confidence score`).
* ✅ Предупреждение, если текст неоднозначен и требует обязательной ручной проверки.

## Документация по данным

<details>
<summary><b>Нажмите, чтобы раскрыть детали о датасете и обработке</b></summary>
<br>

Для демонстрации работы прототипа используется датасет `city_messages.csv` (120 записей).

* **Источник:** Синтетические данные, сгенерированные с помощью LLM на основе реальных паттернов обращений из открытых городских пабликов и чатов.
* **Особенности:** В данных намеренно сохранены типичные особенности реальных обращений: эмоциональная окраска, смешение языков (русский/казахский), опечатки и разговорный стиль.
* **Обработка и безопасность:** Данные очищены от реальных персональных данных (PII) на этапе генерации. Перед отправкой во внешнюю LLM в production-среде планируется внедрение обязательного этапа автоматической анонимизации (удаление ФИО, номеров телефонов) для соблюдения законодательства о персональных данных.
* **Обоснование выбора:** Такой набор позволяет проверить робастность парсера и точность скоринга в условиях, максимально приближенных к реальным, без рисков утечки чувствительной информации.

## Установка и запуск

Для работы требуется **Python 3.9** или выше.

### 1. Подготовка окружения
Склонируйте репозиторий и перейдите в папку проекта:
```bash
git clone https://github.com/13e01/govtech-hackaton-2026.git
cd govtech-hackaton-2026
git checkout kimi-verse
```

Создайте файл `.env` в корневой папке и добавьте ваш API-ключ:
```env
DEEPSEEK_API_KEY=ваш_ключ_здесь
```

### 2. Установка зависимостей
Выберите команду, соответствующую вашей операционной системе:

<details>
<summary><b> Windows</b></summary>

```cmd
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```
</details>

<details>
<summary><b> macOS / Linux</b></summary>

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```
</details>

### 3. Запуск приложения
```bash
streamlit run app.py
```
Приложение откроется в браузере по адресу: `http://localhost:8501`

*(Опционально) Для запуска фонового анализатора датасета без UI:*
```bash
python analyzer.py
```

## ⚠️ Ограничения и дальнейшие шаги

1. **Зависимость от LLM:** Точность извлечения сущностей зависит от качества промпта и возможностей конкретной модели.
2. **Безопасность данных:** В текущем прототипе данные передаются в LLM как есть. Следующий шаг разработки — внедрение локального NLP-модуля (например, на базе `natasha` или `KazNERD`) для удаления PII перед вызовом внешнего API.
3. **Масштабирование:** Для обработки потока >1000 сообщений в минуту потребуется переход от синхронных вызовов к асинхронной очереди задач (Celery + Redis).
