# GovTech Camp 2026 — Умный помощник Ситуационного центра Астаны

**Авторы:** Khan & Aslan

## Проблема

Жители Астаны часто сообщают об авариях, проблемах ЖКХ, дорог и транспорта в неформальных каналах — чатах и социальных сетях. Оператору Ситуационного центра приходится вручную читать неструктурированные, эмоциональные и двуязычные сообщения, отделяя реальные инциденты от рекламы и флуда. Это замедляет реакцию на риски.

## Пользователь

Оператор или аналитик Ситуационного центра Астаны. Сервис готовит карточки обращений, чтобы специалист быстрее увидел критичные сигналы, проверил их и передал в профильную службу.

## AI/ML-подход

`analyzer.py` отправляет текст обращения в DeepSeek API и получает структурированный результат:

- категорию инцидента и нормализованную локацию;
- базовый уровень угрозы (0–50), масштаб (0–20) и бонус за повторяемость обращений (0–20);
- итоговый индекс угрозы 0–100%, триггерные слова и оценку уверенности модели;
- краткие обоснования на русском, казахском и английском.

Повторные сигналы по совпадающей локации увеличивают приоритет. `app.py` отображает результаты в Streamlit, фильтрует их и выводит аналитику без изменения API или маршрутов.

## Explainability и контроль специалиста

В каждой карточке доступны топ-3 фактора результата: угроза, масштаб и повторяемость; также показываются триггеры и уверенность модели в процентах. Уверенность отражает полноту и однозначность сообщения, а не гарантирует точность.

### Ограничения модели

Модель работает только с текстом обращения. Она может ошибиться в категории, адресе или контексте, а сообщение может быть неполным, устаревшим или недостоверным. Результат не заменяет выезд, проверку первоисточников и оценку ответственной службы. **Финальное решение принимает специалист.**

## Документация по данным

- **Источник:** `city_messages.csv` — демонстрационный моделируемый набор обращений жителей Астаны из неформальных каналов (соцсети и чаты), не официальный реестр.
- **Размер:** 120 текстовых сообщений.
- **Используемые признаки:** исходно — `id`, `text`, `source`, `date`; после анализа — категория, локация, обоснования, триггеры, индекс угрозы, бонус повторяемости и уверенность модели.
- **Preprocessing/очистка:** проверяются обязательные поля, дата и числовые значения приводятся к корректному типу; названия локаций нормализуются; флуд отфильтровывается; повторные сообщения по одной локации учитываются в скоринге.
- **Ограничения данных:** набор малый и демонстрационный; сообщения могут содержать эмоции, ошибки и неполные адреса. Их достоверность и привязку к месту должен подтверждать специалист.

## Измеримый эффект

В дашборде вкладка «Данные и эффект» рассчитывает показатели по текущей выгрузке.

- **Экономия времени:** сценарная оценка — около 240 минут первичного ручного разбора для 120 сообщений при норме 2 минуты на сообщение.
- **Снижение ручной нагрузки:** 120 из 120 сообщений получают автоматическую первичную категоризацию и скоринг; человеку остаются проверка и итоговое решение.
- **Приоритизация обращений/рисков:** записи с индексом угрозы от 80% автоматически поднимаются в начало ленты. Их количество отображается на дашборде и обновляется вместе с данными.

Это оценка потенциала для демонстрационного набора, а не результат промышленного замера.

## Запуск проекта

### 1. Подготовить окружение

```bash
python3 -m venv venv
source venv/bin/activate  # Windows (cmd): venv\Scripts\activate.bat
pip install pandas openai streamlit python-dotenv altair
```

Новые зависимости для изменений не добавлялись.

### 2. Настроить ключ

Создайте в корне проекта файл `.env`:

```text
DEEPSEEK_API_KEY=ваш_ключ_от_platform.deepseek.com
```

### 3. Сформировать результаты анализа

```bash
python3 analyzer.py  # Windows: python analyzer.py
```

Скрипт читает `city_messages.csv` и сохраняет результат в `analyzed_city_messages.csv`.

### 4. Открыть дашборд

```bash
streamlit run app.py
```

Откройте в браузере адрес, который выведет Streamlit (обычно `http://localhost:8501`).
